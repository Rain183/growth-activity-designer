# mock 数据包（演示环境数据源导览）

> 本资产包是可独立运行的演示复刻版，不连接公司内部系统。真实环境里，S2 信息装载的动态数据不来自任何单一文件，而是按取数口径分别来自 BI、活动报名系统、交易与客服系统、流量平台、财务与实验平台；**演示环境按同样的结构建表——每类数据一张表，对应一个真实来源系统**。S2 的索取清单写着数据来自哪个系统，就到对应的 mock 表取数。
>
> 覆盖范围与 skill 的能力范围一致：**京东超市域的各类用增活动设计**（拉新/购频/客单价/品类/超市卡储值等诉求都能取到基线），不与任何单一活动绑定。数值为一期自洽快照（时点口径：26年4月第2周），与 `../runs/` 实录内两个完整案例的数字同源。
>
> **本表数值为脱敏演示样本**：与项目交付的真实数字不同（真实口径以项目交付物为准），只保证本沙盒内部自洽。演示口径的完整判读见 `../runs/消费挑战/11-实验判读与定档.md`——先例锚点、判读结果、实验设计三处同源。

## 使用方式

S2 生成索取清单后，把本目录路径给 AI：按索取清单里每条口径标注的来源系统，到对应 mock 表取数；信息底座逐条落"值 + 来源=对应 mock 表 + 时点（26年4月第2周快照）"。

## 表里取不到的数怎么办（演示口径，三条规则）

1. **口径在信息量地图内、但 mock 表没有精确值**：等价于真实环境的"人工请示"——使用者自拟一个合理值，信息底座来源标注"演示假设"，进决策点汇报表请示项；
2. **机制行为率类（参与率/开启率/完成率/核销率）**：新玩法没有事实值——**真实环境同样没有**（没上线的活动谁也没有它的参与率）。到 `bi-历史活动先例.md` 取最接近机制类型的先例区间做基准假设，来源标注"历史活动先例类比（假设）"，对应参数必须标实验位、由实验一验证——这正是"每个数字有公式或来源"在无先例时的标准口径；
3. **信息量地图之外的口径**：S2 本就不允许索取——回到方法论，检查是不是把系统实现或预算管理（业务方职责）的问题带进了方案设计。
