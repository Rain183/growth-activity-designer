# S3 玩法选型与规则设计 · 四步法（本 skill 核心知识文件）

这套顺序来自团队对既有活动人工推演过程的逐步回放：老产品经理想活动，从来不是先想页面长什么样，而是按下面四步走。每一步的产物约束下一步，顺序本身就是方法论。

## 第一步：从目标指标倒查玩法库

- 输入：`01-活动画像.md` 的北极星指标 + `02-信息底座.md` 的可用权益与成本上限。
- 动作：在 `playbooks/` 按"适用指标"字段倒查候选玩法（≥2 个），逐个对照：成本结构是否在成本上限内、权益类型是否在允许清单内、与目标人群状态是否匹配。
- 产出：候选玩法对比表（玩法/作用机制/成本结构/预期风险）+ 推荐结论与排除理由。
- 判据：**每个被排除的候选必须写"为什么不行"**——排除理由与推荐理由同等重要，这是方案评审时最先被追问的部分。

## 第二步：触发规则结构化

触发规则 = **动作 + 条件 + 奖励**，是活动的内核。逐字段填：

| 字段 | 要求 | 易错点 |
|------|------|--------|
| 动作 | 用户做什么（下单/充值/签到/邀请），动词+对象 | 把"参与活动"当动作——参与不是行为，下单才是 |
| 命中条件 | 什么范围算数：商品池口径（自营/POP、必须有有效促销、特殊商品排除清单）、金额口径（实付/卡支付/含不含赠金）、时间窗口 | **把命中条件和发奖条件混为一谈**；金额口径不写"含/不含赠金" |
| 发奖条件 | 何时发：即时发/收货后发/周期累计达标发；累计型写清统计窗口与达标线 | 周期累计型漏写"每期一次还是可循环" |
| 奖励 | 类型+面额/价值+有效期+成本承担方 | 奖励类型与北极星矛盾（如目标是拉充值却奖励赠金——系统白送余额降低充值必要性） |

**杠杆参数（门槛值/返比/档位/上限）一律标注"实验位"，给出候选区间与设定逻辑，不拍死**——最优值由实验判定，方案阶段拍死数字过不了评审。

## 第三步：基本规则逐项过

时间（常驻/周期/单期）、区域、人群（含风控豁免判断）、单用户参与次数与金额上限、活动总发奖上限。每项写决策理由，"意义不大"也要写明为什么不设。

## 第四步：互斥扫描

拿 `02-信息底座.md` 里的在投活动清单逐条扫：
- **权益冲突**：相同/相似用增目标是否重复让利？（目标不同甚至互相成就的，写明理由不互斥）
- **场景冲突**：投放位置是否与在投活动抢同一楼层/标签位？
- 产出：互斥判定表，覆盖在投清单 100%，一条不许跳。

## 产物

`03-活动规则.md`：基本/触发/互斥三表 + 候选玩法对比表。门禁 `check_rules.py` 校验：触发规则四字段齐全带口径、杠杆参数标实验位、互斥扫描覆盖率 100%。
